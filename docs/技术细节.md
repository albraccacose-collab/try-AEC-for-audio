## 能力清单

- **完整闭环**：C# WinForms 界面 → P/Invoke → 原生 AEC3 → 输出 WAV
- **两套 API**：文件级（一行调用处理整个 WAV）+ 流式（逐 10 ms 帧实时处理）
- **可取消**：长文件处理过程中随时中止，约 80 ms 内响应，且不留残缺文件
- **格式预检**：开始处理前就校验采样率/声道/位深，错误信息指名道姓
- **有据可查**：24 项自动化检查（构建/ABI/行为/互操作/音质/GUI），一条命令复现
- **无第三方音频依赖**：测试音频由脚本合成，回声通路已知，ERLE 可量化

界面为单窗口布局：顶部两行「标签 + 路径输入框 + 浏览按钮」（参考音频 / 麦克风录音），
中部为只读日志区，底部是进度条、状态栏和「开始处理 / 播放原始录音 / 播放处理结果 / 取消」按钮。
所有控件使用 `Dock` / `Anchor`，窗口可自由缩放。

```
┌─────────────────────────────────────────────────────────────────┐
│  AecToolApp_2  (C# WinForms, x64)                               │
│                                                                 │
│   UI 界面          音频文件 IO          线程 / 进度 / 取消       │
│   (按钮/进度条)    (System.Media)      (Task.Run + 回调节流)     │
│        │                 │                     │                │
│        └─────────────────┼─────────────────────┘                │
│                          ▼                                      │
│              P/Invoke 桥接层  (NativeAec.cs)                    │
│              - 10 个 extern "C" 函数声明                         │
│              - 委托保活 / 错误码映射 / 取消标志指针              │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 动态加载 aec_api.dll
                           ▼
┌─────────────────────────────────────────────────────────────────┐
│  aec_api.dll   (C ABI 导出层, 本仓库新增)                        │
│  api/aec_c_api.h · api/aec_c_api.cc                             │
│  封装 EchoCanceller3 的生命周期 + 10 ms 分帧处理循环             │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 静态链接
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   ┌────────────┐   ┌────────────┐   ┌────────────┐
   │  AEC3.lib  │   │  api.lib   │   │  base.lib  │
   │ 核心算法   │   │ 工厂+配置  │   │ rtc_base / │
   │ (aec3/)    │   │            │   │ abseil /   │
   │            │   │            │   │ jsoncpp    │
   └────────────┘   └────────────┘   └────────────┘
```

**处理链路（每 10 ms 一帧）**：

```
ref  ──► AudioBuffer ──► SplitIntoFrequencyBands ──► AnalyzeRender ──► Merge
mic  ──► AudioBuffer ──► AnalyzeCapture ──► SplitIntoFrequencyBands
                                    │
                                    ├──► HighPassFilter (100 Hz, 去除直流/低频)
                                    │
                                    └──► ProcessCapture ──► Merge ──► out
```

> ⚠️ `HighPassFilter` **无条件创建**（16 kHz 也有专用系数），
> 早期版本按采样率门控导致 ERLE 从 29.2 dB 掉到 24.2 dB。见[踩过的坑](#踩过的坑)。

## 构建详解

### 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Visual Studio | 2022 (v143 工具集) | 需要「使用 C++ 的桌面开发」工作负载 |
| Windows SDK | 10.0.22621.0 或更高 | |
| .NET Framework | 4.7.2 | C# 侧 |
| PowerShell | 5.1 | 验证脚本 |

### 定位 MSBuild

MSBuild 的实际路径因 Visual Studio 版本与安装位置而异：

```powershell
# 方法一：用 vswhere 查询安装路径
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" `
    -latest -products * -property installationPath

# 方法二：Visual Studio 菜单 → 工具 → 命令行 → 开发者命令提示符
```

拿到路径后（下面的 `<VS>` 代指该路径）：

### 第一步：构建原生侧

```powershell
& "<VS>\MSBuild\Current\Bin\MSBuild.exe" `
    AEC3-master\AEC3.sln /p:Configuration=Debug /p:Platform=x64 /m
```

产出到 `AEC3-master\output\Debug_x64\`：

```
AEC3.lib  base.lib  api.lib  demo.exe  aec_api.dll   ← 关键产物
```

### 第二步：部署 DLL

```powershell
Copy-Item AEC3-master\output\Debug_x64\aec_api.dll AecToolApp_2\bin\x64\Debug\ -Force
```

> `aec_api.dll` 是运行时通过 P/Invoke 加载的，**必须和 exe 同目录**。
> 缺了它程序仍能打开，但会检测到并禁用「开始处理」按钮（优雅降级，不崩溃）。

### 第三步：构建 C# 侧

```powershell
& "<VS>\MSBuild\Current\Bin\MSBuild.exe" AecToolApp_2\AecToolApp_2.sln `
    /p:Configuration=Debug /p:Platform=x64
```

产出 `AecToolApp_2\bin\x64\Debug\AecToolApp_2.exe`。

> **两个解决方案彼此独立，必须先 native 后 C#。**
> C# 的 sln 刻意不引用 C++ 工程：所有 C++ 工程用 `$(SolutionDir)` 定位 include 与输出，
> 跨目录引用会让该变量指向错误位置（表现为满屏 `C1083: 无法打开包括文件`）。

### 一步到位

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify_all.ps1
```

这会自动完成上述全部步骤（含测试音频合成）并跑完 24 项检查。
脚本内的路径全部由**脚本自身位置**推导，因此仓库可以放在任意目录。

## C API 参考

全部符号为 `extern "C"` + `__cdecl`，**无名字修饰**，可直接 P/Invoke。

### 流式 API

| 函数 | 说明 |
|---|---|
| `void* AEC_Create(int sample_rate_hz, int channels)` | 创建实例。采样率必须是 16000/32000/48000，声道必须是 1；失败返回 `NULL` |
| `void AEC_Destroy(void* handle)` | 释放实例，`NULL` 安全 |
| `int AEC_Process(handle, render, mic, out, linear_out, frame_size)` | 处理一个 10 ms 帧，原地写 `out`。`frame_size` 必须等于 `sample_rate_hz/100` |
| `int AEC_SetAudioBufferDelay(handle, delay_ms)` | 设置外部延迟估计。**必须在至少处理过一帧之后调用** |
| `int AEC_GetMetrics(handle, &erl, &erle, &delay_ms)` | 读取指标，任一出参可为 `NULL` |

### 文件 API

| 函数 | 说明 |
|---|---|
| `int AEC_ProcessAudioFiles(ref, mic, out, cb, user)` | 处理整对 WAV，同时输出 `<out>_linear.wav` |
| `int AEC_ProcessAudioFilesEx(ref, mic, out, set_delay, delay_ms, cb, user, abort)` | 同上，可指定延迟并支持取消 |
| `int AEC_GetAudioInfo(path, buffer, buffer_size)` | 可读的文件头描述文本 |
| `int AEC_GetAudioFormat(path, AecAudioFormat* out)` | 结构化格式信息，含 `is_supported` |
| `int* AEC_GetAbortFlag(void)` | 进程级取消标志指针；写非 0 即请求取消 |

## 实测性能

对合成测试对（10 s / 16 kHz / mono）的纯回声段（0.5–3.0 s）测量：

| 指标 | 本工具 (aec_api.dll) | 参考 demo.exe |
|---|---|---|
| **ERLE**（回声抑制量，越高越好） | **35.90 dB** | — |
| 输出 RMS | -68.65 dBFS | — |
| 处理耗时 | ≈ 1.15 s（10 s 音频，约 8.7× 实时） | ≈ 1.07 s |
| 流式 / 文件模式输出一致性 | **SHA-256 完全相同** | — |

对 Microsoft synthetic 数据集（`fileid_0`）：

| 实现 | 纯回声段输出 RMS | ERLE |
|---|---|---|
| `demo.exe` | -60.93 dBFS | 28.92 dB |
| `aec_api.dll` | -61.23 dBFS | **29.22 dB** |
| 与 demo 的逐样本残差 | — | RMS -59.33 dBFS（比输出本身低 22 dB） |

残差来源：demo 每帧把延迟压到 0，而 DLL 让 AEC3 自估（收敛到 32 ms），
两者渲染/捕获对齐略有不同。由于 ERLE 反而更高且残差低于量化台阶，判定为等价。

## 测试音频的构造与选材

### 合成测试对（自包含，推荐）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\make_test_audio.ps1
```

在 `testdata\` 生成三个文件：

| 文件 | 用途 | 界面字段 |
|---|---|---|
| `synth_farend_16k.wav` | 远端参考 | 参考音频 |
| `synth_mic_16k.wav` | 模拟麦克风（含回声） | 麦克风录音 |
| `synth_nearend_16k.wav` | 干净近端目标（**不是输入**） | 仅用于算 ERLE |

构造方式：`mic = farend * RIR + nearend + noise`，
其中 RIR 为 32 ms 直达 + 3 个衰减反射，前 3 秒近端**数字绝对静音**
（因此那 3 秒是纯回声段，ERLE 可无歧义测量）。

### 兼容：Microsoft AEC-Challenge 数据集

仓库**不包含**第三方音频。如需真实录音，可从
[microsoft/AEC-Challenge](https://github.com/microsoft/AEC-Challenge) 下载
`datasets/synthetic/` 下的三元组（必须**同一个 fileid**）：

```
farend_speech_fileid_N.wav       → 参考音频
nearend_mic_signal_fileid_N.wav  → 麦克风录音
nearend_speech_fileid_N.wav      → 干净目标（算 ERLE 用）
```

> ⚠️ **不要用 `datasets/real/` 的 `*_lpb.wav` / `*_mic.wav` 验证 AEC。**
> 该目录 README 明确说明 *"Some PCs may have DSP processing in the send and/or
> receive path, even though we used a raw mode"*。实测其 ref/mic 互相关峰值**仅 0.0826**、
> ERL **-0.5 dB** —— 系统音频 DSP 已把回声消掉，软件 AEC 无回声可消。
> 用它会得出"程序跑通但无法证明有效"的结论。

## 踩过的坑

改造过程中遇到并修复的真实问题，记录下来避免重蹈：

| # | 问题 | 根因 | 影响 |
|---|---|---|---|
| 1 | `LNK2019` ×3 + `LNK1120` | `AEC3.vcxproj` 源文件清单**漏掉** `false_comfort_noise_generator.cc` | 整个 sln 无法构建 |
| 2 | **ERLE 24.17 → 29.22 dB** | 抽层时把 `HighPassFilter` 按采样率门控，而 demo **无条件创建**（16 kHz 也有专用系数） | 白丢 4.75 dB 消回声能力 |
| 3 | `AEC_Process` 首帧崩溃（`0x80000003`） | 在推送任何渲染块**之前**调 `SetAudioBufferDelay`，让空缓冲区被套上非零延迟 | 无法处理任何音频 |
| 4 | `AudioBuffer::CopyTo` 断言失败 | 默认构造的 `AudioFrame` 其 `samples_per_channel_` 为 **0**，`CopyTo` 前必须先 `UpdateFrame` 定帧长 | 同上 |
| 5 | 干净重建 `LNK1104: 无法打开 api.lib` | 只写 `AdditionalDependencies` 不会建立构建顺序；须对静态库 `ProjectReference` 开 `LinkLibraryDependencies` | **增量构建会掩盖它** |
| 6 | C# 构建静默通过却跑旧代码 | `build_cs_test.ps1` 吞掉了 `csc` 的错误，留下**陈旧的 exe** | 一度在拿过期结果做判断 |
| 7 | `$(SolutionDir)` 跨目录失效 | 全部 5 个 C++ 工程靠 `$(SolutionDir)` 定位 include；挂到别的目录的 sln 下就全错 | `C1083` 满屏 |
| 8 | 32 位 exe 加载 64 位 DLL | sln 把 `Debug\|x86` 映射到了项目的 `Debug\|AnyCPU`，而后者输出 `bin\Debug\` | 必然失败 |

**方法论教训**：

- 抽层类改造**必须跑一次 `/t:Rebuild`** —— 增量构建会掩盖链接顺序问题（坑 5）
- **"假绿"比报错更危险** —— 测试脚本必须让编译失败变成硬错误（坑 6）
- 凡是 demo **无条件执行**的 DSP 环节，抽层时必须**原样保留**（坑 2）

## 路线图：加入 ANC 降噪

目前只有 AEC。下一步计划接入 **ANC（Active Noise Cancellation，主动降噪 / 噪声抑制）**。

### 目标

在保留 AEC 回声消除能力的前提下，抑制近端稳态环境噪声
（风扇、空调、键盘、街道噪声），提升近端语音清晰度。

### 关键约束与设计要点

1. **顺序不能随意**。业界标准是 **AEC 在前、NS 在后**：
   AEC 先把回声压下去，NS 才不会被回声干扰误判为噪声。
   若反过来，NS 会先削弱回声参考，AEC 的自适应滤波器将难以收敛。
   ```
   ref ──► AEC ──► NS ──► out
   mic ──►      ──►
   ```

2. **注意算法延迟**。WebRTC 的 `NoiseSuppressor` 工作在 10 ms 帧、
   16 kHz 定点域，与现有 AEC3 分帧一致，接口层面可直接串接。
   但其内部有 VAD 与平滑，会引入额外延迟，需重新评估 `SetAudioBufferDelay` 取值。

3. **双讲保护**。ANC 在双讲段容易误伤近端语音，需借助 AEC3 已有的
   `GetMetrics()`（ERL/ERLE、延迟）或独立的近端检测来判断何时降低抑制强度。

4. **可量化验收**。现有 `tools/compare_outputs.ps1` 已能算 ERLE；
   加入 ANC 后需要新增指标：
   - **降噪量** = 纯噪声段 `10*log10(mic²/out²)`
   - **近端失真** = 近端单讲段 `10*log10(Σ(out-target)² / Σtarget²)`
     （正好可以用合成音频的 `synth_nearend_16k.wav` 作 target）
   - 需要扩展 `tools/make_test_audio.ps1`，加入纯噪声段与带噪近端语音

5. **ABI 保持向后兼容**。计划以**新增导出**而非修改现有签名的形式接入：
   ```c
   AEC_API int AEC_CALL AEC_SetNoiseSuppression(void* handle, int level);
   AEC_API int AEC_CALL AEC_GetNoiseMetrics(void* handle, double* noise_reduction_db, ...);
   ```
   现有 10 个符号的行为保持不变，C# 侧无需改动即可继续工作。
